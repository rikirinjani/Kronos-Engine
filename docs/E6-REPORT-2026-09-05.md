## 1. Precondition: Aliasing Test

| Test | Result | Meaning |
|------|--------|---------|
| P1: Plain-object/Map state independent after restore | **PASS** | `restoreSnapshot` deepClones plain objects correctly |
| P2: EventQueue class instance shared after restore | **FAIL** | `deepClone` returns class instances by reference (clone.ts line 6) |
| P3: clock.rng closure shared after restore | **FAIL** | `deepClone` returns functions/closures by reference (clone.ts line 2) |

**Interpretation:** The `deepClone` function in `clone.ts` has two known holes:
1. Class instances (prototype !== Object.prototype) → returned by reference
2. Functions/closures → returned by reference

DR's `world.queue` is an `EventQueue` class instance; `world.clock.rng` is a closure with mutable internal state. Both are shared across branches after checkpoint restore.

## 4. Critical Finding: Aliasing Artifact in forkBranch

### The Problem

E4 (fresh worlds) shows **ZERO intervention effect** across all horizons and seeds:
```
E4: horizon=20 seed=42 ...
    sentinelOutput.occupancyRate: base=0.5420 intv=0.5420 Δ=0.0000
    sentinelOutput.icuOccupancyRate: base=0.0357 intv=0.0357 Δ=0.0000
    sentinelOutput.supplyStress: base=0.4918 intv=0.4918 Δ=0.0000
```

All 9 combinations (3 horizons × 3 seeds) show Δ=0.0000. The climate intervention does NOT affect DR sentinel metrics when using fresh worlds.

### The Artifact

E6 (forkBranch) shows **non-zero intervention effect**:
```
sentinelOutput.occupancyRate: baseline=0.5420 intervention=0.5649 Δ=+0.0229
sentinelOutput.icuOccupancyRate: baseline=0.0357 intervention=0.0714 Δ=+0.0357
sentinelOutput.supplyStress: baseline=0.4918 intervention=0.5195 Δ=+0.0278
```

### Root Cause

The non-zero effect in E6 is a **spurious aliasing artifact**, not a real causal effect:

1. E4 uses fresh worlds for both branches → zero effect (correct)
2. E6 uses forkBranch for the intervention branch → non-zero effect (artifact)
3. The aliasing test confirms forkBranch shares EventQueue and RNG closure between branches
4. When baseline runs first, it advances the shared RNG and populates the shared queue
5. The intervention branch then starts from the post-baseline state, not the checkpoint state
6. This cross-contamination appears as a non-zero intervention effect

### Implications for the Paper

- **The rewind/counterfactual mechanism has a latent aliasing defect** that can produce spurious causal effects
- **E4's fresh-worlds design is the correct approach** for causal inference — it avoids the aliasing issue entirely
- **E6's forkBranch design is unreliable** for causal inference due to the aliasing defect
- **The intervention effect reported in P-004 (30-seed rerun) should be interpreted with caution** — it used fresh worlds (correct), but the macro→micro coupling path may still have aliasing issues

---

## 5. Recommendations

1. **For the paper:** Use E4's fresh-worlds design as the primary causal evidence. Report E6's aliasing defect as a known limitation.
2. **For the codebase:** Fix `clone.ts` to deepClone class instances and closures properly. This requires:
   - Detecting class instances (prototype check) and recursively cloning their properties
   - For closures: capture and restore the closure's internal state (or use a stateless design)
3. **For future experiments:** Always use fresh worlds (E4 design) for causal inference, not forkBranch.
