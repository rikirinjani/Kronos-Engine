## 🔴 Critical

### 1. Cadence spec/implementation mismatch
**P-005 proposal says:** `cadence?: number` (optional, defaults to 1)
**Code says (`src/sectors/types.ts:32`):** `cadence: number` (required)
**Impact:** If a new sector is added without a `cadence` field, TypeScript will refuse to compile. The optional spec was designed for backward compatibility — new sectors would inherit behavior (tick every turn) without explicitly declaring it. The implementation forces explicitness, which is arguably better but contradicts the approved spec.

### 2. Contract file drift — 2 sources of truth
| Author | Location | Files | Format |
|--------|----------|-------|--------|
| Meta Platform | `src/sectors/*/CONTRACT.md` | 7 | Verbose: includes RNG position, O(n) complexity, invariants |
| Sector Engineer | `src/sectors/contracts/*.md` | 8 | Tabular: state keys, events emitted/handled, cross-sector links |

**Impact:** When a sector changes, which file gets updated? Neither agent knew the other was writing contracts. The P-005 spec defined one format but the Sector Engineer used a different one. Both formats are now canonical by default — there's no single source of truth.

**Extra issue:** Sector Engineer named the adapter contract `deers-rock-sentinel.md` while Meta Platform named it `deers-rock-adapter/CONTRACT.md`. Different names for the same entity.

## 🟠 Moderate

### 3. CI workflow duplication
| Workflow | What it runs | Trigger |
|----------|-------------|---------|
| `ci.yml` | tsc → vitest → vitest --coverage → verify-facts | push + PR |
| `coverage.yml` | vitest --coverage → vitest tests/ | push only |
